# ADR-003: Existing forecasting adapter and explicit fallback

- **Status:** Proposed (Assignment 1)
- **Decision owners:** Project team (student)
- **Scope:** Smart Shopping AACC architecture

## Context
Course Overview prohibits model training/fine-tuning; recommendation needs predictions without creating a synchronous high-latency dependency.

## Decision
Use an interchangeable adapter to an existing forecast implementation or non-trained baseline; precompute forecasts in batch and store version and time. Return labelled rules-only or unavailable output on failure.

## Alternatives considered
Train own RNN; call model per UI request; make prediction a mandatory dependency.

## Consequences / trade-offs
Complies with course ground rule and protects latency; forecast quality is constrained by available data/model suitability and needs later evaluation.
