# ADR-007 — Route every model call through an LLM gateway with guardrails

**Status:** Accepted (2026-11-25)

## The problem

The assistant uses an LLM, which is stateless, can invent facts, can be steered by untrusted text (product and retailer names), costs energy and money per call and may be unavailable. The course treats the engineering around the model call (the harness) as the larger part of the work.

## Our decision

All model calls go through the LLM Gateway, composed of an Input Guardrail, a Model Router, Cache and Memory, an Output Guardrail and a Trace Log. The model receives only a structured evidence payload, runs with fixed sampling settings and has no tools; we deliberately deploy no agent. The router applies a worth-it gate (is a model call needed and affordable at all?) and decides which model to use (cache, template, small local, large external; see [ADR-015](ADR-015.md)) from the evidence state, the intent, the operating mode and the budget. The output guardrail checks schema, grounding of every number and date, agreement of the action label with the rule result and the absence of guarantees; a failed check is retried once and then replaced by a template and flagged. Every exchange is traced with an estimated energy value, and flagged exchanges go to an operator review queue.

## Options we considered

- **Call the provider directly from the Assistant Service:** no central place for cost, safety, caching and logging; each feature would repeat them.
- **Always use the largest model, no router:** highest cost and energy and no reaction to the carbon mode.
- **Let an LLM do the routing:** adds a model call to decide on a model call; rules are enough for four intents.
- **Semantic cache:** saves more calls but risks serving an answer for a different situation; an exact cache keyed by the evidence hash is safer for the MVP.
- **Adopt an off-the-shelf gateway product:** viable later; the MVP keeps thin modules behind the same interface so the choice stays open.

## What this means for the project

More components and tests are needed, including a golden evaluation set, and the checks add latency and occasional retries that cost energy. In return the provider can be swapped (NFR-07), failures degrade to templates (NFR-04), and cost, energy and quality become visible.
