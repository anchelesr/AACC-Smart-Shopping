# ADR-016 — No autonomous agent: a fixed, bounded workflow around the model call

**Status:** Accepted (2026-11-25), approved by the authors on the proposal of this session.

## The problem

An agent is a language model that chooses tools and steps by itself. It can adapt to tasks that were not planned, but every tool is attack surface, every loop costs tokens and energy, and behaviour is harder to audit. We must decide whether an agent is worth it for Smart Shopping, measured by value, cost, risk, control and energy.

## Our decision

We do **not** deploy an agent. The assistant runs a **fixed workflow with a hard step limit**: guardrail, router (ADR-015), one model call, output check, at most one retry with the error message, optional escalation, template fallback. The model has no tools, never writes to any system and never decides the advice, the mode or the placement; those stay deterministic rules.

The decision is reviewed at each revision and immediately if one of these triggers occurs: (1) a use case needs data that is not in the evidence payload and a measured gain is expected; (2) the fixed workflow stays below the groundedness target on the golden set and an analysis shows that a lookup would fix it; (3) the energy and token budget leave measurable headroom. An agent could then be introduced only with read-only tools on an allow-list, a step limit, a token limit per task, full tracing and a shadow period.

## Options we considered

| Criterion | No model, rules only | Fixed workflow (chosen) | Agent with read-only tools |
| --- | --- | --- | --- |
| Value for the shopper | Low for free-text questions | Medium: language where it helps | Higher only if data outside the payload is needed, which our use cases do not require |
| Cost and energy | Lowest | Bounded: at most two calls | Unbounded without a limit; several calls per task |
| Risk (injection, wrong action) | Lowest | Low: no tools, output checked | Higher: every tool is attack surface |
| Control and audit | Full | Full: fixed steps, one trace per exchange | Hard: the path differs per request |
| Fit with energy modes | Trivial | Router follows the mode | Hard to cap in AMBER and RED |

## What this means for the project

Free-text follow-ups are limited to what the evidence payload supports; anything else is answered with a template notice. We keep a record of questions the assistant could not answer, which is the evidence for the review under trigger 1 or 2. In return the assistant is cheap, auditable and consistent with the energy modes.
