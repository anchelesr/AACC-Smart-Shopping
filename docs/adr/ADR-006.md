# ADR-006 — Show forecast age instead of silently serving stale advice

**Status:** Accepted (2026-11-25)  
**Revision note:** Extended in revision 2 to cover the assistant.

## The problem

The scheduler may intentionally postpone a refresh, and a worker or model may fail. Neither case should be hidden from the shopper, and price browsing must not depend on the current state of the model.

## Our decision

Read the latest stored forecast with its timestamp and status (FRESH, STALE or MISSING). Use the forecast in the advice rules only while it is fresh; otherwise show observed prices and the history with a clear notice, and let the advice rely on the rules that need no forecast or return Insufficient Evidence. The assistant restates the same result and the same caveat.

## Options we considered

- **Block until a fresh forecast is calculated:** ties page latency to background work.
- **Silently show the old forecast:** faster but misleading.
- **Hide advice whenever the forecast is not fresh:** safe but throws away the still useful price evidence.

## What this means for the project

The interface and the assistant must handle several evidence states, not only success and failure. This protects the shopper experience during forecast outages as long as the price database is reachable; a full database outage is a separate availability issue.
