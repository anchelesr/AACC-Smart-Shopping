# ADR-006: Serve stored forecast with transparent staleness

- **Status:** Proposed (Assignment 1)
- **Decision owners:** Project team (student)
- **Scope:** Smart Shopping AACC architecture

## Context
Interactive SLA should not depend on a long-running forecast; high-carbon periods may delay refresh.

## Decision
Serve last stored forecast with generated-at and status while within configured acceptability; otherwise mark forecast unavailable and keep current-price features working.

## Alternatives considered
Block until current forecast is produced; silently serve stale values.

## Consequences / trade-offs
Good fail-soft user experience and predictable API latency; user may see older estimates and UI must display quality caveats.
