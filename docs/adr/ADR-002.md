# ADR-002: Relational persistence with provenance

- **Status:** Proposed (Assignment 1)
- **Decision owners:** Project team (student)
- **Scope:** Smart Shopping AACC architecture

## Context
Current and historical offers must be linked by retailer, product, time and source; forecasts and jobs need durable status.

## Decision
Use PostgreSQL normalized tables with unique upsert constraints and explicit observation provenance.

## Alternatives considered
Flat CSV only; document database.

## Consequences / trade-offs
Reliable query/consistency and SQL tooling; schemas and backups increase operations overhead. Demo dataset may still be imported from CSV.
