# ADR-001: Modular API plus separate batch workers

- **Status:** Proposed (Assignment 1)
- **Decision owners:** Project team (student)
- **Scope:** Smart Shopping AACC architecture

## Context
The course emphasizes justified architecture; the MVP has a modest catalog but needs independent control of interactive latency and batch forecasts.

## Decision
Use one modular FastAPI backend with internal business modules, and isolated importer / forecast worker containers.

## Alternatives considered
One monolith for everything; many fine-grained microservices.

## Consequences / trade-offs
Simpler interfaces, testability and independently scalable workloads; extra scheduling and deployment units compared with a single process.
